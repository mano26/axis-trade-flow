1 — Workflow Overview

Every trade follows the same sequence. Completing each step in order ensures the ticket and cards are accurate before printing.

  1. Enter the trade string on the Orders page and submit. The system parses the string and creates a confirmed order record.
  2. Record a fill once the trade is done. Enter the filled quantity (may be partial).
  3. Save leg prices — enter the price for each leg. The system validates that leg prices reconcile to the stated package premium.
  4. Save counterparties — enter the filling broker, counterparty, and bracket for each lot allocation.
  5. Print cards and ticket — only available once all counterparties are allocated.
For partial fills, repeat steps 2–4 for each partial. Each fill gets its own counterparty allocation. Cards and tickets always reflect the complete order.

2 — Order Entry & Ticket Numbering

Entering an Order

Type the trade string in the entry box on the Orders page and click Submit Order. The system parses the string, validates it, and assigns the next sequential ticket number. House and Account can be set before submitting using the dropdowns below the entry box — they default to the values most recently used.

Ticket Numbering System

Every order gets a four-digit ticket number: 0001 through 9999. The counter advances by one for each new order. At the end of the day the counter wraps — the first order the following morning picks up from where the prior day left off (or from 0001 if the previous day ended at 9999). Hard-deleting an order frees its ticket number and the system reuses it for the next order created.

Setting the First Ticket of the Day

To force a specific starting ticket number — for example to begin a new day at 0001, or to match an off-system sequence — use the Ticket # field in the page header next to the date. Type the desired number before submitting the order. That order will take the number you entered, and subsequent orders auto-increment from there. Leave it blank to let the system assign the next number automatically.

The Ticket # field is available to all users. If the number you enter is already in use today the system will reject it and prompt you to choose another.

Editing a Ticket Number After the Fact

Company admins and super admins can change a ticket number on an existing order — even after it has been filled — by clicking the small ✎ pencil icon next to the order number on the order detail page. Enter the corrected four-digit number and click Save. The number must be unused on that order's trade date. The change is written to the audit log.

If you need to reuse a ticket number that was assigned to a wrong or duplicate order, delete the original order first (which frees the number) and then re-enter the correct order using the Ticket # override field.

3 — Trade String Syntax

The general structure is:

<contract> <strike(s)> <C/P> <strategy> [ratio] <price_format>

Contract Codes

Use standard CME Globex codes for SOFR options. Examples:

SFRH6 SFRM6 SFRU6 SFRZ6 SFRH27 SFRM7 SFRU7 SFRZ7 0QH6 0QM6 2QZ6

Short-dated pack codes (0QN6, 2QM6, etc.) are recognised automatically.

Strikes

List one or more strikes as decimals after the contract code. Order does not matter — the system sorts them correctly for each strategy.

SFRH6 96.25 CS 4/500 <- one strike per leg inferred SFRH6 96.00 96.25 CS 4/500 <- explicit strikes SFRH6 95.75 96.00 96.25 C FLY 2/200

Option Type

Use C or CALL for calls, P or PUT for puts. For strategies that imply a type (CS, PS, BFLYC, BFLYP, etc.) the type token may be omitted.

5 — Price Format & Direction

The price/quantity token tells the system both the package premium and the direction of the trade.

Buy (Debit)

price/qty e.g. 4/500 (pay 4 ticks for 500 lots)

The number before the slash is the price in ticks. The number after is the quantity.

Sell (Credit)

qty@price e.g. 500@4 (collect 4 ticks on 500 lots)

Spaces around @ and / are accepted: 500 @ 4 and 500@4 both work.

Prices are in ticks. The system converts to decimal internally (4 ticks = 0.04 points). Tick size for SOFR options is 0.25 of a basis point (0.0025), so 4 ticks = 0.01 points.

6 — Advanced Modifiers

Ratio Spreads

Add a ratio token like 1X2, 1X3, or 1X2X1 to create unequal-leg structures. The base quantity from the price format is multiplied by each ratio number.

SFRU6 96.3125 96.1875 P 1X2 7.5/4000 <- buy 4000 @ 96.3125, sell 8000 @ 96.1875 SFRH6 96.00 96.25 96.50 C FLY 1X2X1 2/200

CVD (Covered / Delta Hedge)

Appending CVD <futures_price> D <delta%> adds a futures leg to the trade at the specified delta.

SFRH6 96.00 C 3/500 CVD 96.38 D 40 <- buy 500 calls, sell 200 futures (40% delta) SFRH6 96.00 C 3/500 CVD 96.38 D 40 (+) <- force futures to buy side SFRH6 96.00 C 3/500 CVD 96.38(-) D 40 <- force futures price to sell

VS — Opposing Segments

VS splits a trade into two segments going in opposite directions — the standard calendar/spread-of-spread separator.

SFRM6 96.00 C VS SFRU6 96.00 C 4/500 <- buy M6, sell U6 call

By default the first segment takes the direction of the price format (buy for /, sell for @). To specify which segment is the buy/sell without reordering, add a contract code in parentheses at the end of the string. The named contract takes the price-format direction; the other flips.

SFRM6 96.375 ^ VS SFRU6 96.50 ^ 16/1000 <- buys M6, sells U6 (default) SFRM6 96.375 ^ VS SFRU6 96.50 ^ 16/1000 (SFRU6) <- sells M6, buys U6 SFRM6 96.375 ^ VS SFRU6 96.50 ^ 1000@16 (SFRU6) <- buys M6, sells U6
The parenthetical hint must be an exact contract code (e.g. SFRU6, SFRH7, 0QM6). Anything else — a note, a number, a strike — is stripped and ignored as usual.

WITH — Same-Direction Segments

WITH splits a trade into two or more segments going in the same direction. Use it when the two segments have different strategies or different contracts.

SFRM6 96.75 ^ WITH SFRZ6 96.00 C stupid 25/1000 <- buy straddle AND buy call SFRM6 96.00 96.25 PS WITH SFRM6 97.50 98.00 CS stupid 10/200

STUPID / STRIP

Modifiers that indicate all segments go the same direction (no direction flip).

  • STUPID — same-direction 2-segment trade
  • STRIP — same-direction 3+ segment trade (typically multiple contracts, same strike)
SFRU6 96.00 96.25 C stupid 4/500 <- buy both calls SFRM7 SFRU7 SFRZ7 SFRH8 99.00 C strip 45/750 <- buy all 4 contracts

Bracket Wrapper [ ]

Wrap multiple comma-separated segments in square brackets with a shared price/quantity at the end. Each segment inside uses its own contract and strategy but shares the package price.

[SFRH6 C 96.00, SFRM6 P 95.50] 4/500

7 — Quarter-Tick Check

When a trade price falls on a 0.25-tick increment (e.g. 2.25 ticks, 4.75 ticks) rather than a half-tick or whole-tick, the system pauses and asks for confirmation before submitting.

A dialog will appear:

  • OK — the contract month is quarter-tick eligible. Submit as a parsed trade.
  • Cancel — submit as a generic trade so you can enter legs manually.
Quarter-tick pricing is only valid for eligible expiry months. If you are unsure, click Cancel and enter as generic.

8 — Generic Trade Mode

For complex or non-standard trades that the parser cannot handle, check the Generic Trade box before submitting. The trade string is stored as a reference but the system does not attempt to parse it into legs.

After creating a generic order:

  1. Go to the order detail page. The legs table will be empty and fully editable.
  2. Enter each leg manually: B/S, volume, market, contract, expiry, strike, C/P.
  3. Click Save Legs. You can add or remove rows before saving.
  4. Then proceed with Record Fill → Save Prices → Save Counterparties as normal.
The package premium from the trade string is used to validate prices on a generic order. Make sure the total net dollar value of all legs (qty × price) divided by the total order quantity equals the stated premium.

Split fills / averaged prices: You can enter the same side as two rows at different prices to represent an average fill. For example, two buy rows at 500 lots each for a 1000-lot order. Price validation will average them against the stated premium correctly.

9 — Recording Fills & Partial Fills

Single Fill

On the order detail page, enter the fill quantity in the Record Fill section and click Record Fill. For a complete fill enter the remaining quantity (pre-filled by default).

Partial Fills

Enter a quantity less than the total to record a partial fill. The order status becomes PARTIAL FILL. Repeat as needed — each partial fill gets its own set of prices and counterparties. The balance remains open for additional fills.

When printing tickets on an order with multiple partial fills, each fill generates its own ticket card showing that fill's prices and lot size. A FILL 1 OF 2 — 3,500 LOTS label appears in the top-right to identify each card.

Save Prices

Enter the price for each leg in the Confirmation Legs table. When there are multiple pending fills, prices are saved to the oldest unallocated fill first. The system validates that prices reconcile to the package premium before saving. For generic orders, validation uses the actual fill quantity as the per-lot normaliser, so manually entered leg volumes always reconcile correctly regardless of order size.

Save Counterparties

For each fill enter the filling broker, counterparty symbol, bracket, and quantity. Quantities must sum to the fill quantity. Once saved the fill status becomes ALLOCATED.

If you record a second partial before allocating the first, both pending fills will appear with separate entry forms. Work from top to bottom — allocate the earliest fill first.

10 — CVD & Futures Qty on Counterparty Entry

What is CVD?

CVD (Contains Vs Delta) is a trade that pairs an options leg with a futures leg used to hedge the delta. The options and futures are on opposite sides of the trade (e.g. BUY PUT + BUY FUT, or SELL CALL + BUY FUT). When you enter counterparty quantities on a CVD trade, the futures quantity for each counterparty is calculated automatically from their options quantity and the trade's delta percentage.

Delta Percentage and Futures Qty

The delta % is displayed on the order detail page (e.g. Δ 63%). It is derived from the parsed trade string: futures volume ÷ total options quantity, expressed as a percentage. For a standard CVD, every counterparty's futures allocation is:

Futures Qty = floor(Options Qty × delta%)

The result is floored (rounded down) to a whole number of contracts. This means on odd-lot trades, or when a large order is split across many counterparties, the calculated futures quantities may not sum exactly to the total futures volume. If there is a rounding shortfall, adjust one counterparty's futures quantity manually.

Odd-lot example: 3,000-lot order at 63% delta = 1,890 futures. Split 1,200 / 1,800 across two counterparties:
floor(1,200 × 0.63) = 756  |  floor(1,800 × 0.63) = 1,134  →  total 1,890. ✓

Split 1,000 / 2,000:
floor(1,000 × 0.63) = 630  |  floor(2,000 × 0.63) = 1,260  →  total 1,890. ✓

Split 1,500 / 1,500 (equal halves):
floor(1,500 × 0.63) = 945  |  floor(1,500 × 0.63) = 945  →  total 1,890. ✓

If the totals don't add up, add the shortfall to the largest counterparty's futures qty.

Overriding the Auto-Calculated Futures Qty

Each counterparty row shows a Futures Qty field pre-filled by the delta calculation. You can type a different number to override it — the field accepts any positive integer. An override is appropriate when:

  • You need to correct a rounding shortfall across counterparties
  • The broker confirmed a slightly different futures allocation
  • The order was filled at a different effective delta than the trade string implied

The system does not validate that per-counterparty futures quantities sum to the order's total futures volume — that reconciliation is your responsibility before printing.

Multi-Expiration Futures (Two Futures Legs)

Some CVD strategies use two separate futures expirations — for example SFRZ7 as the primary hedge and SFRM8 as a secondary. When the trade string includes two futures legs, the counterparty entry form shows two Futures Qty columns: Futures Qty (1st exp) and Futures Qty (2nd exp). Each is calculated independently using the same delta formula, and each can be overridden independently.

Make sure to allocate futures for both expirations on multi-leg CVD trades. Leaving the second futures qty at zero will produce incorrect broker cards.

Non-CVD Futures Trades

If the trade string contains only a futures leg and no options leg (i.e. an outright futures order), there is no delta calculation. The counterparty entry form shows a single quantity field for the futures contracts, which you fill in the same way as any other outright trade.

11 — Cards & Tickets

Cards and tickets are available from the order detail page once fills are allocated. Three buttons appear in the Actions section:

Print Cards

One card per leg per bracket. Each card shows the quantity, contract/month, strike, premium, counterparty, and bracket. For spread and CVD trades the bracket letter is suffixed with 6 (e.g. K6) to indicate a spread. Quantities are scaled by the leg's ratio relative to the base lot size — for a 1×2 spread the 2× leg shows double the allocated lots.

Print Ticket

One ticket per fill. For orders with multiple partial fills a separate ticket is generated for each fill, each showing that fill's prices and size. A FILL 1 OF 2 — 3,500 LOTS label appears in the top-right when there are multiple fills. All prices print with at least two decimal places.

Print Ticket + CPs

Generates one broker card per filling broker per fill. Each card shows:

  • The full trade grid at the top (all legs with that fill's prices)
  • A counterparty table below, split by trade side
  • For CVD trades with opposite-side option/futures: the option quantities appear on the option side, futures quantities on the futures side
  • For CVD trades with same-side option/futures (e.g. BUY PUT + BUY FUT): a combined OPT / FUT column on that side
  • For spread + CVD (options on both sides): the futures quantities appear alongside options on whichever side the futures belong to
  • The filling broker box at the bottom right

The bracket column shows the bracket letter suffixed with 6 for any trade that has more than one leg (spreads, flies, CVD, etc.).

Use your browser's Print function (Ctrl+P). The print stylesheet removes the navigation bar and formats each card to 3.5×5.5 inches, each ticket to 8×5.5 inches.

12 — Amending a Trade

After a fill is fully allocated you can still correct it. On the order detail page, find the allocated fill in the Counterparties section and click Edit.

The amendment form lets you change:

  • Leg prices (re-validated against the package premium)
  • Filling broker, counterparty, and bracket for each allocation
  • House and account

Save Amendment commits both price and counterparty changes in a single transaction. The order status updates to AMENDED and a full before/after record is written to the audit trail.

Correct Trade String

For super admins only. If the wrong expiry or contract code was entered (e.g. H6 instead of H7), click the brown Correct Trade String button in the Actions bar. This opens a dedicated page showing the current leg structure and a form to enter the corrected trade string.

Only the contract code and expiry reference are updated — strikes, volumes, option types, sides, prices, and counterparties are not changed. A reason is required for the audit log. Reprint cards and tickets after correcting.

To amend the trade structure itself (strikes, strategy, direction) use the Modify Order button. This re-parses a new trade string and rebuilds the legs.

13 — Correcting, Deleting & Marking Duplicate Orders

Overview

AXIS provides three ways to deal with a problematic order: mark it as a duplicate (soft removal for compliance), hard-delete it (physical removal, ticket number reclaimed), or bulk-delete multiple orders at once from the Order Log. All three operations require Company Admin or Super Admin access. Standard users cannot remove or cancel orders.

Mark as Duplicate

Use Mark as Duplicate when an order was accidentally entered twice and you need to suppress it from volume reports without physically removing it. On the order detail page, the Mark as Duplicate button appears in the Actions bar for admins.

  • The order status changes to CANCELLED DUPLICATE
  • The order record is retained — it remains visible in the Order Log with its original ticket number
  • The order is excluded from all volume totals and EOD summaries
  • Cards and tickets can still be printed if needed for the audit trail
  • A reason is not required, but the action is written to the audit log
Mark as Duplicate is the preferred option when compliance requires keeping a record. Hard-delete is irreversible and loses the audit trail for that ticket number.

Delete Order (Hard Delete)

Use Delete Order to permanently remove an order from the system. This is appropriate for test orders, entry errors caught immediately, or orders entered on the wrong date.

  • The order row is permanently removed from the database — it cannot be recovered
  • The ticket number is freed and immediately becomes eligible for reuse (it will be assigned to the next order if the counter reaches that number)
  • If the deleted order held the highest ticket number of the day, the tenant's ticket counter is reset to the previous highest number, so the sequence continues without a gap
  • Fills, prices, and counterparties associated with the order are also removed
Delete Order is irreversible. The ticket number will be reused. Only delete orders that should never have existed. For orders that were legitimately worked but should be suppressed, use Mark as Duplicate instead.

Editing the Ticket Number

After an order is filled you may discover the ticket number needs to be changed — for example if orders were entered out of sequence and the numbers don't match the physical paper trail. Admins can edit the ticket number directly from the order detail page:

  1. Open the order detail page
  2. Click the ✎ pencil icon next to the ticket number in the page header
  3. Enter the new ticket number (1–9999) and click Save

The system checks that the new ticket number is not already in use on the same trade date. If it is, the save is blocked and a warning is shown. The change is recorded in the audit log with the old and new ticket numbers.

If you need to completely rebuild an order — change the quantity, price, strategy, and counterparties — the simplest approach is to delete the incorrect order and re-enter it from scratch. The ticket number from the deleted order will be available to reuse if needed, or you can force any specific ticket number using the Ticket # field on the Order Entry form.

Bulk Delete (Order Log)

Admins can delete multiple orders at once from the Order Log page. This is useful for clearing a batch of test or duplicate orders.

  1. Navigate to Order Log and use the date range and filters to locate the orders
  2. Check the checkbox next to each order to delete (or use the Select All checkbox in the header)
  3. Click Delete Selected — a confirmation dialog will appear
  4. Type DELETE exactly (all caps) in the dialog and click OK

All selected orders are permanently removed in a single operation. The ticket counter is adjusted for each deleted order using the same logic as a single hard delete. The action is written to the audit log with a list of deleted ticket numbers.

Bulk delete is permanent and cannot be undone. Double-check your selection and date filters before confirming.

Setting the First Ticket of the Day

By default, the first order of each day gets ticket number 0001. If your firm's paper trail started at a different number — for example if some orders were processed offline before AXIS was opened — you can force the starting number using the Ticket # field on the Order Entry form (top-right of the Trade Entry page). All users can set this field; it applies to that single order only.

  • Leave the field blank to use the next auto-incremented number
  • Enter a specific number (e.g. 0023) to force that order's ticket number
  • If the entered number is higher than the current counter, the counter advances to that number so subsequent auto-incremented orders continue from there
  • If the entered number is lower than or equal to the current counter, the counter is not changed — only this one order gets the specified number
Ticket numbers wrap from 9999 → 0001 at the end of each day's sequence. Gaps in the sequence caused by deleted orders are not automatically back-filled — the counter only moves forward.

14 — Modifying the Balance

When an order is partially filled and you need to revise what's still working — whether the price, quantity, or structure has changed — use the Modify Balance button on the order detail page. It is only visible when the order is in PARTIAL FILL status.

How it works

Clicking Modify Balance opens a form where you enter the trade string for what still needs to be filled — not the full original order, just the remaining balance. The system will:

  1. Close the original order at its filled quantity (status becomes PARTIAL CANCELLED)
  2. Update the closed order's trade string to show the actual filled quantity (e.g. 4/2000 becomes 4/800)
  3. Open a new OPEN order with the next sequential ticket number, copying house and account from the original

Example

Original order: SFRZ6 96.125 96.25 96.375 C FLY 4/2000 — 2000 lots working at 4 ticks. You fill 800 lots. Now the client wants to work the balance differently — they want to add a CVD and increase to 4000 lots at 4.5 ticks:

SFRZ6 96.125 96.25 96.375 C FLY CVD 95.965 D 10 4.5/4000

After submitting:

  • Original order #0162 closes at 800 lots — trade string updates to 4/800, status becomes PARTIAL CANCELLED
  • New order #0163 opens for 4000 lots with the butterfly + CVD structure at 4.5 ticks
  • Each order has its own ticket number, cards, and tickets
  • The new order's fills validate against the new structure and price

What to enter as the balance string

Enter only what still needs to be filled — the parser treats it as a fresh order. You can:

  • Change price only — same structure, different price/qty: SFRZ6 96.125 96.25 96.375 C FLY 4.5/1200
  • Change quantity — same structure, more or fewer lots: SFRZ6 96.125 96.25 96.375 C FLY 4/500
  • Add CVD — add a futures hedge that wasn't on the original: SFRZ6 96.125 96.25 96.375 C FLY CVD 95.965 D 10 4/4000
  • Change structure entirely — if the trade has shifted, enter a completely different strategy

Display after modify

The closed order shows its actual filled quantity in all views — Orders page, Order Log, and EOD Summary. A 4/2000 order filled at 800 lots will display as 4/800 (PARTIAL CANCELLED). The new balance order displays normally as a fresh open order.

If the client wants both fills on the same ticket number — enter partial fills sequentially on the same order without using Modify Balance. Each fill records its own prices and counterparties, and Print Ticket + CPs generates one broker card per fill under the same ticket number. Only use Modify Balance when the underlying order terms (price, structure, or quantity) have changed.

15 — Order Log

The Order Log shows all orders across any date range. Use the filters to search by:

  • Date range — defaults to today
  • Ticket number — type a full or partial number
  • Strategy — type the strategy code (e.g. cs, bflyc, ptree)
  • House — partial match
  • Account — partial match
  • Search — searches the raw trade string (e.g. type SFRK6 to find all trades on that contract)

Click any row to open the order detail. Cards and tickets are accessible directly from the log for filled orders.
